# Escalation Brief Template

Use this template when a responsible owner needs a concise issue summary and a clearly stated decision request.

The purpose of escalation is not to transfer responsibility upward without analysis. It is to place the decision with the correct owner and provide enough evidence to act.

## Subject line

```text
Decision required: [process / issue] — [hold / approval / exception / restart / remediation]
```

## 1. One-sentence issue statement

```text
A consequential action is proposed while [material evidence / control / ownership / validation] remains [missing / incomplete / ineffective / unresolved].
```

## 2. Decision requested

```text
Please decide whether to:
- proceed;
- proceed with stated conditions;
- approve a limited pilot;
- accept a time-limited exception;
- hold for additional evidence;
- freeze, reject, or exit the path.
```

## Short-form escalation example

```text
Decision required: Hold release pending full-range validation

The proposed release would reduce reversibility while a material validation gap remains.

Verified facts:
- a local correction was completed;
- only a limited check has been performed;
- the full operating range has not been verified.

Unknowns:
- secondary effects across the full range;
- accountable acceptance of residual risk.

Evidence direction: -
Risk signal: Red

Recommendation:
Hold release, complete the defined validation, document results, and return the decision to the accountable owner.
```

## Quality standard

A useful escalation brief:

- states the action and decision required;
- separates facts from inference;
- identifies the control gap;
- explains consequence and reversibility;
- names the owner;
- gives proportionate options;
- states what would reverse the recommendation;
- remains short enough to review.

## Use boundary

This template supports issue escalation and decision communication. It does not replace required emergency, safety, legal, regulatory, privacy, security, engineering, financial, or management procedures.
